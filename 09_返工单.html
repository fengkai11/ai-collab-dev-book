AI 协同开发：切片式开发训练手册

第 9 章：如何写返工单，判断该返工产品还是返工实现

版本：v0.2 核心训练扩写版
本章定位：核心训练章节

本章你要学会什么

你要学会把“感觉不对”变成 coding agent 能执行的返工任务，并判断问题到底该改产品定义还是改代码。

为什么这一章重要

AI 协同开发最容易失败的地方，往往不是模型不会写代码，而是人没有把目标、边界、检查点和验收方式定义清楚。本章的作用，是把一个容易凭感觉推进的环节，变成可以重复执行的训练动作。你不需要一开始掌握传统软件工程的全部知识，但你必须能把 AI 的输出限制在自己能审查、能判断、能返工的范围内。

核心概念

  • 产品返工：目标、流程、交互、文案需要改。
  • 实现返工：需求明确但代码没做到。
  • 复现步骤：让别人重复看到问题。
  • 当前结果：系统实际表现。
  • 期望结果：你希望的表现。
  • 修改范围：本次允许改哪里。
  • 返工复验：修完后重新检查。

核心观点

  1. 返工不是重新做，而是最小修正。
  2. 产品返工和实现返工要分开。
  3. 不好用不是返工单。
  4. 返工也要写做/不做边界。
  5. 每次返工后必须复验相关项。

主案例推进

模拟问题：确认按钮位置不明显；空输入仍可提交；状态文案显示处理中而不是待执行；coding agent 自行加入员工配置页。分别判断为产品/交互、实现、实现或需求未定义、越界实现。

错误示范

这个页面不好用，你优化一下。

这会导致 AI 随机优化，甚至改动无关页面。

正确示范

请只修复以下 3 个问题，不要新增功能，不要改无关页面：1. 空输入时按钮应禁用；2. 确认按钮放到草案卡片右下角；3. 初始状态文案应为待执行。修复后对照验收项说明是否通过。

方法拆解

1. 从验收失败项开始

返工单最好来自验收记录。

2. 写复现步骤

例如打开页面、不输入、点击生成。

3. 写当前结果

按钮可点击并生成空草案。

4. 写期望结果

按钮应禁用，不能生成草案。

5. 判断问题类型

需求未定义先产品返工，需求清楚但没做到才实现返工。

6. 限定修改范围

只改任务创建页，不改权限、审批、路由。

7. 要求复验

修复后说明相关验收项是否通过。

返工单要避免“二次发散”

返工阶段最容易出现二次发散。原因是你已经看到了一些问题，情绪上会想“干脆一起优化”。但这样会让返工变成新一轮大开发。正确做法是：一个返工单只修验收失败相关问题。

如果你发现了新想法，先写到“下一切片候选”，不要塞进本次返工。

返工单中的范围限制示例

允许修改：
- 任务创建页；
- 草案确认组件；
- 任务列表组件；
- 与上述组件直接相关的本地状态逻辑。

不允许修改：
- 路由结构；
- 全局布局；
- 登录注册；
- 权限相关文件；
- 审批页面；
- 员工配置页面；
- 与第一切片无关的样式系统。

这类范围限制能显著减少 coding agent 顺手重构。

产品返工示例

问题：用户生成草案后，不知道是否还可以编辑。
原因：页面预览没有说明草案字段是可编辑的，也没有编辑态样式。
处理：先修改页面预览和验收标准，再施工。

返工单：

请调整草案确认区交互：
1. 草案字段应以可编辑输入框形式展示；
2. 每个字段旁不需要单独编辑按钮；
3. 确认创建前用户可以修改标题、目标、交付物；
4. 不改任务列表，不新增审批。

实现返工示例

问题：产品合同和验收清单都要求空输入禁用，但实现中按钮仍可点击。
处理：直接实现返工。

返工单：

修复空输入提交问题。
复现步骤：打开页面，不输入内容，点击生成任务草案。
当前结果：按钮可点击并生成空草案。
期望结果：输入为空时按钮禁用，不能触发生成。
只修改任务输入区相关逻辑，不改其他页面。

越界实现处理

如果 coding agent 自行加入了员工配置页，不要说“这个也挺好，先留着”。第一切片阶段，越界内容会干扰验收。你可以选择：

  1. 删除；
  2. 隐藏；
  3. 移到后续分支；
  4. 记录到下一切片候选。

返工话术：

本次第一切片不包含员工配置页。请移除页面入口和相关展示，不要继续实现配置功能。如果相关文件已新增，请在变更说明中列出，并说明是否删除或保留为未引用文件。

返工后复验规则

返工后不要全量乱测，先复验相关项，再做一次核心链路冒烟测试。

1. 复验返工相关验收项；
2. 走一遍正常主流程；
3. 检查是否引入越界功能；
4. 记录是否通过；
5. 如果失败，再写下一张返工单。

返工提示词增强版

你是 coding agent。请只执行下面返工单，不要新增功能，不要顺手优化。
如果你认为需要改动无关文件，必须先说明原因。
返工完成后，请逐条说明复验项是否通过，并列出所有变更文件。

v0.2 核心训练扩写：把“感觉不对”变成可执行返工单

本节扩写第 9 章。目标是让读者学会把验收失败项变成 coding agent 能准确修复的返工任务。

9.1 返工不是重做，而是最小修正

很多新手发现 AI 写出来的东西不对时，会直接说：

不对，重写一下。

或者：

这个页面不好用，优化一下。

这两句话都会让返工失控。

返工的目标不是让 coding agent 重新发挥一次，而是针对已经发现的问题做最小修正。

返工单要回答：

  1. 哪个验收项没通过？
  2. 如何复现？
  3. 当前结果是什么？
  4. 期望结果是什么？
  5. 只允许改哪里？
  6. 不允许顺手改哪里？
  7. 修完后复验哪些项？

如果这些问题没写清，返工很容易引入新问题。

9.2 产品返工和实现返工必须分开

这是第 9 章最重要的判断。

实现返工

实现返工指：产品合同、施工单或验收清单已经写清楚，但 coding agent 没做到。

例子：

验收标准写了：空输入不能生成草案。
实际结果：空输入仍然生成草案。

这就是实现返工。

产品返工

产品返工指：原来的产品定义不清、交互设计不合理、字段设计不完整，需要你重新定义产品规则。

例子：

草案确认按钮应该放在哪里，之前没有定义。现在发现用户不容易看到。

这更接近产品返工。你要先决定按钮位置和交互规则，再让 coding agent 修改。

待确认问题

有些问题暂时不能直接归类。

例子：

风险等级默认是低、中、高，还是只显示是否高风险？

这属于待确认。不能让 coding agent 自己决定。

9.3 主案例问题分类

假设第 8 章验收后发现 4 个问题。

问题 A：确认按钮不明显

当前结果：生成草案后，确认创建按钮在页面底部，用户需要滚动才能看到。
期望结果：确认创建按钮应该位于草案卡片右下角。

分类：产品 / 交互返工。

原因：按钮位置属于交互决策。如果之前页面预览没写清，需要先补充产品定义。

问题 B：空输入仍可提交

当前结果：输入框为空时点击生成草案，系统生成了空草案。
期望结果：空输入时按钮禁用或提示请输入任务描述。

分类：实现返工。

原因：验收清单已明确要求空输入不能生成草案。

问题 C：任务状态显示为“处理中”

当前结果：确认后任务状态显示为处理中。
期望结果：状态应为待执行。

分类：实现返工。

原因：施工单明确写了初始状态为“待执行”。

问题 D：多了员工配置页

当前结果：页面出现员工配置入口。
期望结果：本切片不出现员工配置。

分类：越界实现，需要返工删除或隔离。

原因：施工单明确不做员工配置。

9.4 三组错误返工 vs 正确返工

组 1：模糊反馈

错误返工：

这个页面不好用，你优化一下。

正确返工：

请只修复确认按钮不明显的问题。
当前结果：生成草案后，确认创建按钮位于页面底部，用户需要滚动才能看到。
期望结果：确认创建按钮放在草案卡片右下角，并使用主按钮样式。
不允许改动：不要修改任务列表、草案字段、页面路由和其他功能。
复验项：草案生成后能看到确认按钮；点击确认后任务仍能进入列表。

组 2：要求整体重做

错误返工：

这个实现不符合预期，重新做任务创建功能。

正确返工：

请只修复以下两个实现偏差：
1. 空输入时仍可生成草案。
2. 确认后状态显示为“处理中”，应改为“待执行”。
不要重构页面，不要改动草案字段，不要新增功能。

组 3：顺手扩展

错误返工：

顺便把审批功能也加上。

正确返工：

本次返工只修复第一切片问题，不新增审批功能。审批功能放入下一切片计划。

9.7 主案例返工单示例一：空输入仍可生成草案

# 返工单：修复空输入仍可生成草案的问题

## 1. 关联信息

关联切片：任务创建 → 草案确认 → 入列表
关联验收项：验收项 4：空输入不能生成草案
问题类型：实现返工
优先级：高

## 2. 问题描述

任务输入框为空时，用户仍然可以点击“生成草案”，系统会生成一个空草案。

## 3. 复现步骤

前置条件：打开任务创建页。
操作步骤：
1. 保持任务输入框为空。
2. 点击“生成草案”按钮。
3. 查看草案区域和任务列表。

## 4. 当前结果

系统生成了一个标题为空或内容为空的草案。

## 5. 期望结果

空输入时不应生成草案。可以采用以下任一方式：
1. “生成草案”按钮置为禁用状态；或
2. 点击后提示“请输入任务描述”。

推荐优先使用按钮禁用，同时保留输入校验提示。

## 6. 修改范围

允许修改：
1. 任务输入框校验逻辑。
2. 生成草案按钮禁用状态。
3. 空输入提示文案。

## 7. 不允许改动

不要修改：
1. 草案字段结构。
2. 任务列表样式。
3. 任务状态文案。
4. 路由结构。
5. 不要新增审批、执行、权限等功能。

## 8. 复验清单

修复后请复验：
1. 空输入时不能生成草案。
2. 输入有效任务后仍能生成草案。
3. 生成草案后仍能确认创建。

## 9. 完成后请汇报

1. 修改了哪些文件。
2. 如何验证空输入已被拦截。
3. 是否影响正常任务创建流程。

9.8 主案例返工单示例二：移除越界员工配置入口

# 返工单：移除第一切片中的员工配置入口

## 1. 关联信息

关联切片：任务创建 → 草案确认 → 入列表
关联验收项：验收项 8：页面不出现本切片之外的功能
问题类型：越界实现
优先级：中

## 2. 问题描述

当前页面出现了“员工配置”入口，但第一切片明确不做员工配置功能。

## 3. 复现步骤

前置条件：打开任务创建页或任务列表页。
操作步骤：
1. 查看页面顶部导航和侧边栏。
2. 查找是否存在“员工配置”入口。

## 4. 当前结果

页面显示“员工配置”入口，点击后可能进入未完成页面。

## 5. 期望结果

第一切片页面不显示员工配置入口。员工配置功能放入后续切片，不在当前页面暴露。

## 6. 修改范围

允许修改：
1. 当前页面导航配置。
2. 当前切片相关入口显示逻辑。

## 7. 不允许改动

不要修改：
1. 任务创建主流程。
2. 草案生成逻辑。
3. 任务列表状态逻辑。
4. 不要实现员工配置功能。

## 8. 复验清单

1. 页面不再显示员工配置入口。
2. 任务创建流程仍可正常完成。
3. 任务列表仍显示待执行状态。

9.9 产品返工示例：确认按钮位置不明显

产品返工要先补产品定义，再改实现。

# 产品返工确认：草案确认按钮位置

## 问题

生成草案后，确认创建按钮位置不明显，用户可能不知道下一步操作。

## 当前定义缺口

原页面预览只写了“确认创建按钮”，没有定义按钮位置、样式和出现时机。

## 新产品规则

1. 草案生成后，在草案卡片右下角显示“确认创建任务”主按钮。
2. 按钮在草案未生成前不显示。
3. 草案字段为空时按钮禁用。
4. 点击后任务进入列表，并清空草案区域。

## 转成实现返工

请按照上述新产品规则调整确认创建按钮。不要改动任务列表、草案字段结构和页面路由。

这个例子说明：产品返工不应该直接丢给 coding agent 猜。先把产品规则补清楚，再变成实现返工。

9.10 产品返工 vs 实现返工判断表

| 现象 | 判断 | 原因 |
|---|---|---|
| 合同写了空输入不能提交，但实际可以提交 | 实现返工 | 已定义但没做到 |
| 页面按钮位置不明显，原文档没定义位置 | 产品返工 | 需要补交互规则 |
| 系统多了本版不做的员工配置页 | 越界实现 | 违反不做边界 |
| 风险等级字段到底要不要显示不确定 | 待确认 | 需要业务决策 |
| 状态文案与施工单不一致 | 实现返工 | 期望已明确 |
| 用户路径走不通，因为原流程设计不合理 | 产品返工 | 需要重新定义流程 |

9.16 读者常见卡点

卡点 1：总想让 AI “整体优化”

整体优化通常会引入新问题。返工阶段要克制，只修已发现问题。

卡点 2：不会写期望结果

期望结果来自三个地方：产品合同、施工单、验收清单。如果三者都没写，那就是产品返工，需要先补定义。

卡点 3：返工后忘记复验

返工后不复验，就不知道修复是否真的生效，也不知道有没有引入新问题。

卡点 4：让 coding agent 决定产品规则

不要把“按钮放哪里”“状态叫什么”“风险等级怎么分”这类问题完全丢给 coding agent。它可以建议，但最终要你确认。

返工能力决定了你能不能真正把 AI 开发拉回正轨。

不要把“不好用”丢给 AI，要把它翻译成复现步骤、当前结果、期望结果和修改边界。

当你能稳定写返工单时，你就不再害怕 AI 第一次做不对。因为你已经掌握了把偏差一点点修回来的方法。
