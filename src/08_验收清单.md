# 第 8 章：如何用验收清单做非程序员也能执行的验收

> 版本：v0.2 核心训练扩写版  
> 本章定位：核心训练章节

## 本章你要学会什么

你要学会不用看懂全部代码，也能通过验收清单检查 AI 开发结果。验收不是感觉一下，而是逐条测试。

## 为什么这一章重要

AI 协同开发最容易失败的地方，往往不是模型不会写代码，而是人没有把目标、边界、检查点和验收方式定义清楚。本章的作用，是把一个容易凭感觉推进的环节，变成可以重复执行的训练动作。你不需要一开始掌握传统软件工程的全部知识，但你必须能把 AI 的输出限制在自己能审查、能判断、能返工的范围内。

## 核心概念

- 验收清单：可执行检查项。
- 正常流程：用户按预期操作。
- 异常流程：输入错误、生成失败、重复点击等。
- 边界情况：空输入、长输入、刷新、多次创建。
- 页面验收：结构、按钮、文案。
- 状态验收：待执行、生成中、失败等状态。

## 核心观点

1. 非程序员也能验收产品结果。
2. 验收清单应在施工前准备。
3. 验收覆盖正常、异常和边界。
4. 每条要能标记通过/未通过/不确定。
5. 验收结果应直接转成返工单。

## 主案例推进

对第一切片验收：空输入是否禁用，输入后能否生成草案，草案是否可编辑，确认后是否进入列表，状态是否为待执行，是否出现越界功能。

## 错误示范

```text
我打开页面看了看，感觉还可以，按钮能点，页面没报错。
```

这不是验收，因为没有覆盖异常、边界和状态。

## 正确示范

```text
验收项：空输入时生成按钮应禁用。
操作：打开页面，不输入内容。
当前结果：按钮仍可点击。
期望结果：按钮禁用。
结论：未通过。
```

## 方法拆解

### 1. 从成功标准转验收项

把“空输入不能提交”改成具体操作和期望结果。

### 2. 覆盖正常流程

输入任务、生成草案、编辑、确认、列表显示。

### 3. 覆盖异常流程

生成失败、空输入、重复点击、草案为空。

### 4. 覆盖边界情况

长输入、连续创建、刷新页面、越界功能。

### 5. 记录结论

通过、未通过、不确定、本版不要求。

## 常见误区

### 误区：验收就是随便点点

验收必须有清单和记录。

## 验收清单应在施工前写

很多人等代码做完才想怎么验收，这会导致验收标准被结果反向影响。更稳的做法是在施工前写验收清单，并把它放进施工任务单里。这样 coding agent 施工时就知道完成标准。

流程应该是：

```text
切片定义 → 验收清单 → 施工任务单 → 实现 → 按清单验收
```

而不是：

```text
实现 → 看看效果 → 临时想怎么验收
```

## 验收项的好坏对比

差的验收项：

```text
页面要好用。
```

好的验收项：

```text
打开页面后，不输入任何内容，“生成任务草案”按钮应禁用。
```

差的验收项：

```text
AI 生成合理草案。
```

好的验收项：

```text
输入“帮我整理本周客户跟进情况”后，草案至少包含标题、目标、交付物、风险等级四个字段。
```

差的验收项：

```text
列表正常显示。
```

好的验收项：

```text
点击确认创建后，任务列表新增一行，显示任务标题、创建时间、风险等级和状态“待执行”。
```

## 主案例完整验收清单扩展

### 正常流程

1. 打开页面，应看到页面标题“创建 AI 员工任务”。
2. 输入框为空时，生成按钮禁用。
3. 输入任务描述后，生成按钮可点击。
4. 点击生成后，按钮进入 loading 状态。
5. 生成成功后，出现草案确认区。
6. 草案包含标题、目标、交付物、风险等级。
7. 用户可以编辑草案标题。
8. 用户可以编辑交付物描述。
9. 点击确认创建后，出现成功提示。
10. 任务列表新增任务，状态为“待执行”。

### 异常流程

1. 空输入不能生成草案。
2. 生成失败时显示错误提示。
3. 生成失败后保留用户输入。
4. 生成中重复点击不会创建重复草案。
5. 草案标题为空时不能确认创建。

### 边界情况

1. 输入 500 字长任务描述，页面不崩溃。
2. 连续创建 3 条任务，列表显示 3 条。
3. 任务列表为空时有引导文案。
4. 页面刷新后如果数据不保留，应在产品合同中标明本版不要求持久化。
5. 页面不出现员工配置、权限、审批等越界功能。

## 验收结果如何记录

建议用这样的记录：

```text
验收项编号：A-02
操作：打开页面，不输入内容。
期望：生成按钮禁用。
实际：按钮可点击。
结论：未通过。
问题类型：实现问题。
复现稳定性：每次必现。
```

这条记录可以直接变成返工单。

# v0.2 核心训练扩写：让非程序员也能验收 AI 写出来的东西

> 本节扩写第 8 章。目标是把“看着差不多”变成“按清单逐条验收”。

## 8.1 验收不是感觉，而是证据

很多新手用 AI 写完代码后，会打开页面点几下，然后说：

```text
感觉还行。
```

或者：

```text
好像哪里不对，但说不上来。
```

这就是没有验收清单的问题。

验收不是让你变成程序员，也不是要求你读懂所有代码。验收的核心是：把产品结果拆成一条条可以手工检查的证据。

你只需要回答：

1. 我做了什么操作？
2. 页面应该出现什么结果？
3. 实际出现了什么结果？
4. 这一项通过、失败还是不确定？
5. 如果失败，如何复现？

这 5 个问题足够让你对 AI 产出形成控制。

## 8.2 验收清单应该在施工前准备

很多人等 coding agent 做完以后才想怎么验收，这会导致一个问题：你会被最终页面牵着走。

正确做法是：在施工前就把验收清单写好。这样施工单和验收清单会互相约束。

施工前写验收清单有三个好处：

1. 你能提前发现切片定义不清。
2. coding agent 知道完成标准。
3. 返工时有明确依据。

主案例中，如果施工前就写了：

```text
空输入时不能生成草案。
```

那么 coding agent 做完后，你只要测试这一项。如果它没做到，就不是“感觉不好”，而是明确失败项。

## 8.3 一条好验收项的 4 个字段

一条验收项建议包含：

```text
前置条件：测试前页面处于什么状态。
操作步骤：用户具体怎么操作。
期望结果：页面应该发生什么。
通过标准：满足什么才算通过。
```

例如：

```text
验收项：空输入不能生成草案
前置条件：任务创建页已打开，任务输入框为空。
操作步骤：点击“生成草案”按钮。
期望结果：系统不生成草案，并提示用户先输入任务描述，或按钮处于禁用状态。
通过标准：空输入不会进入草案生成流程，也不会新增任务。
```

这就比“空输入要处理好”清楚得多。

## 8.4 主案例验收清单：任务创建第一切片

### 正常流程验收

```text
验收项 1：输入任务后能生成草案
前置条件：任务创建页已打开。
操作步骤：在输入框输入“帮我整理本周客户开发情况”，点击“生成草案”。
期望结果：页面出现加载态，随后展示任务草案卡片。
通过标准：草案卡片包含任务标题、任务目标、预期产出、风险等级。
```

```text
验收项 2：草案字段可以编辑
前置条件：草案卡片已生成。
操作步骤：修改草案标题或预期产出字段。
期望结果：字段内容可以被用户修改。
通过标准：修改后的内容能保留在草案卡片中。
```

```text
验收项 3：确认后任务进入列表
前置条件：草案卡片已生成。
操作步骤：点击“确认创建”。
期望结果：任务出现在任务列表中。
通过标准：列表中显示修改后的任务标题，状态为“待执行”。
```

### 异常流程验收

```text
验收项 4：空输入不能生成草案
前置条件：任务输入框为空。
操作步骤：点击“生成草案”。
期望结果：按钮禁用，或页面提示“请输入任务描述”。
通过标准：不会出现草案卡片，也不会新增任务。
```

```text
验收项 5：草案生成失败时有提示
前置条件：系统模拟草案生成失败。
操作步骤：输入任务并点击“生成草案”。
期望结果：页面显示失败提示。
通过标准：用户能看到“草案生成失败，请重试”之类的明确提示，且可以再次尝试。
```

### 边界情况验收

```text
验收项 6：重复点击不会创建多个草案
前置条件：输入框已有任务描述。
操作步骤：快速多次点击“生成草案”。
期望结果：生成过程中按钮禁用或只触发一次生成。
通过标准：不会出现多个重复草案。
```

```text
验收项 7：确认创建后不会重复入列表
前置条件：草案卡片已生成。
操作步骤：快速多次点击“确认创建”。
期望结果：只创建一条任务。
通过标准：任务列表中不会出现重复任务。
```

### 越界功能验收

```text
验收项 8：页面不出现本切片之外的功能
前置条件：打开任务创建页和任务列表页。
操作步骤：查看页面全部按钮、入口、菜单。
期望结果：不出现审批、真实执行、员工配置、权限、长期记忆等功能入口。
通过标准：页面只包含任务创建、草案确认和任务列表相关内容。
```

## 8.5 三组错误验收 vs 正确验收

### 组 1：只说感觉

错误验收：

```text
页面还可以，就是感觉不太顺。
```

正确验收：

```text
失败项：确认创建按钮位置不明显。
复现步骤：生成草案后查看草案卡片底部，没有明显主按钮。
期望结果：确认创建按钮应位于草案卡片右下角，并使用主按钮样式。
```

### 组 2：没有复现步骤

错误验收：

```text
空输入有问题。
```

正确验收：

```text
前置条件：任务输入框为空。
操作步骤：点击“生成草案”。
当前结果：系统生成了一个空草案。
期望结果：按钮禁用或提示请输入任务描述，不应生成草案。
```

### 组 3：把产品问题和实现问题混在一起

错误验收：

```text
状态不对，页面也不好看，整体重做。
```

正确验收：

```text
问题 1：确认后列表状态显示为“处理中”，但产品合同要求为“待执行”。这是实现偏差。
问题 2：确认按钮位置是否应该调整，产品合同未定义，需要产品返工确认。
```

## 8.11 验收结果如何转成返工输入

验收不是结束，验收失败项会进入第 9 章的返工单。

转换方法如下：

| 验收失败项 | 返工单字段 |
|---|---|
| 验收项编号 | 关联验收项 |
| 操作步骤 | 复现步骤 |
| 实际结果 | 当前结果 |
| 期望结果 | 期望结果 |
| 问题类型 | 产品返工 / 实现返工 |
| 严重程度 | 优先级 |

示例：

验收失败项：

```text
验收项 4：空输入不能生成草案。
实际结果：空输入时仍然生成了草案。
```

转成返工输入：

```text
问题：空输入时仍可生成草案。
复现步骤：打开任务创建页，保持输入框为空，点击生成草案。
当前结果：出现空草案。
期望结果：按钮禁用或提示请输入任务描述，不生成草案。
问题类型：实现返工。
```

## 8.12 练习扩写与参考答案

### 练习 1：把成功标准转成验收项

成功标准：

```text
草案可编辑。
```

参考验收项：

```text
前置条件：任务草案已生成。
操作步骤：点击任务标题字段，修改标题内容。
期望结果：标题字段可以编辑并保留修改后的内容。
通过标准：确认创建后，列表中显示修改后的标题。
```

### 练习 2：补全异常流程

正常流程：输入任务 → 生成草案 → 确认创建。

参考异常流程：

```text
1. 空输入时点击生成草案。
2. 草案生成失败。
3. 生成过程中重复点击按钮。
4. 草案为空时点击确认创建。
5. 确认创建失败。
```

### 练习 3：写主案例验收清单

参考答案可使用 8.4 的验收项 1–8。

### 练习 4：判断验收项是否可执行

验收项：

```text
A. 系统要足够智能。
B. 空输入时不能提交。
C. 页面体验要好。
D. 确认后任务状态显示为待执行。
```

参考答案：

```text
可执行：B、D。
不可执行：A、C。
```

原因：A 和 C 都是主观表达，没有操作步骤和通过标准。

参考记录：

```text
结果：未通过
实际表现：输入框为空时点击生成草案，系统生成了标题为空的草案。
是否进入返工：是
问题类型：实现问题
```

### 练习 6：从验收结果提炼问题

## 8.13 读者常见卡点

### 卡点 1：不会判断问题类型

先不用追求完全准确。你可以初步判断：

- 合同写了但没做到，多半是实现问题。
- 合同没写清，导致不知道对不对，多半是产品问题或待确认。
- 出现本版不做的功能，是越界实现。

### 卡点 2：不想写复现步骤

没有复现步骤，coding agent 很难稳定修复。复现步骤越清楚，返工越可控。

### 卡点 3：觉得验收太慢

验收慢一次，返工会快很多。没有验收清单，你可能会反复说“还是不对”，但每次都说不清哪里不对。

### 卡点 4：页面好看但流程不对

不要被视觉骗了。第一切片优先验收流程、状态、边界，再验收美观。
