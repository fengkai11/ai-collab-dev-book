AI 协同开发：切片式开发训练手册

第 6 章：如何给 GPT 下达切片任务，让它不发散

版本：v0.2 核心训练扩写版
本章定位：核心训练章节

本章你要学会什么

你要学会把 GPT 从自由发挥模式拉回切片协作模式。好提示词的核心不是更长，而是边界更清楚。

为什么这一章重要

AI 协同开发最容易失败的地方，往往不是模型不会写代码，而是人没有把目标、边界、检查点和验收方式定义清楚。本章的作用，是把一个容易凭感觉推进的环节，变成可以重复执行的训练动作。你不需要一开始掌握传统软件工程的全部知识，但你必须能把 AI 的输出限制在自己能审查、能判断、能返工的范围内。

核心概念

  • 输出边界：本轮输出什么、不输出什么。
  • 禁止展开：防止 GPT 写后端、数据库、权限等内容。
  • 待确认项：不确定内容不脑补。
  • 单轮目标：每次只让 GPT 完成一种任务。
  • 验收导向：把描述改成可检查表达。

核心观点

  1. GPT 默认倾向补全和扩展，必须显式限制。
  2. 好提示词不是更长，而是规定本轮只做什么。
  3. 每轮只完成一种任务。
  4. 让 GPT 列待确认项，比让它默默脑补更安全。
  5. 要把感觉不对改成明确约束。

主案例推进

围绕第一切片，与 GPT 的对话应分轮：审查产品合同、输出页面预览、收紧切片边界、生成施工单、生成验收清单。每轮只做一件事。

错误示范

基于这个 AI 员工系统，请帮我生成完整开发文档。
继续深入。
帮我优化一下。

这些都容易发散，因为没有边界、没有输出格式、没有禁止展开。

正确示范

请只围绕“任务创建 → 草案确认 → 任务进入列表”这个第一切片工作。
不要展开审批、执行、记忆、工具调用、权限。
本轮只输出页面预览、切片边界、待确认项。

方法拆解

1. 写背景

一句话说明项目和当前切片。

2. 写本轮目标

例如本轮只输出页面预览。

3. 写禁止范围

列出不做审批、执行、记忆、权限等。

4. 写输出格式

规定标题和字段，减少自由发挥。

5. 要求待确认项

所有不确定内容放待确认项。

6. 要求可验收

所有标准都改成能手工检查。

和 GPT 的对话演示

请基于下面产品合同，只输出第一切片页面预览。
禁止：后端、数据库、接口、审批、执行、长期记忆、权限。
输出：页面列表、区块、按钮、状态、待确认项。

常见误区

误区：提示词越长越好

长但没边界仍会发散。

误区：让 GPT 一轮做所有事

每轮只做一种任务。

误区：不让 GPT 暴露不确定性

待确认项是防脑补机制。

本章小结

GPT 很会扩展。你要用当前切片、本轮目标、禁止范围、输出格式和待确认项，把它限制在可控范围内。

下一章如何接上

下一章把切片转成 Claude Code / Codex 可执行的施工任务单。

提示词的“刹车系统”

给 GPT 的提示词里，要有刹车。刹车不是一句“不要发散”就够了，而是具体写清楚什么叫发散。

例如：

以下内容视为发散：
1. 写数据库设计；
2. 写后端接口；
3. 设计权限系统；
4. 加入员工配置；
5. 讨论部署；
6. 设计长期记忆。

这样 GPT 才知道边界在哪里。

三种常用收敛句式

句式 1：只做当前层

本轮只做页面预览，不写代码、不写接口、不写数据库。

句式 2：只做当前切片

本轮只围绕任务创建与草案确认，不展开审批、执行、记忆、权限。

句式 3：不确定就问

无法从材料中确定的内容，请放入待确认项，不要替我做默认决定。

这三句话可以组合使用。

“继续”之前先指定方向

新手常说“继续”，但 GPT 不知道继续哪里。你要把“继续”改成下面几种：

继续扩写验收清单，不要写实现。
继续补充异常流程，不要改正常流程。
继续审查越界功能，不要重写方案。
继续把成功标准改成可验收表达。
继续把页面预览收敛成施工单。

这样 GPT 的输出会稳定很多。

主案例连续三轮完整示范

第 1 轮：生成产品合同

我想做 AI 员工任务系统。请不要写完整 PRD。
请只生成一页纸产品合同，字段包括目标用户、核心问题、本版闭环、成功标准、本版不做、待确认项。
本版只考虑任务创建与草案确认。

第 2 轮：页面预览

基于上面的产品合同，请只输出页面预览。
禁止写后端、数据库、接口、权限、审批、执行。
页面预览要包含区块、按钮、点击结果、空状态、加载态、错误态。

第 3 轮：收敛施工边界

基于页面预览，请输出第一切片边界。
只写本切片做什么、不做什么、哪些可以 mock、验收标准。
不要写代码。

这三轮的顺序非常重要。不要跳过前两轮直接施工。

GPT 输出越界时的修正话术

你刚才的输出中包含了本切片不做的内容，例如【列出】。
请重新输出，只保留任务创建与草案确认闭环。
把审批、执行、权限、记忆放到“后续切片”，不要展开。

注意不要直接说“你错了，重写”。要明确指出哪里越界、如何处理。

提示词质量自评

每次发送提示词前，快速检查：

[ ] 我写了当前切片吗？
[ ] 我写了本轮只做什么吗？
[ ] 我写了禁止展开吗？
[ ] 我写了输出格式吗？
[ ] 我要求不确定内容放待确认项了吗？
[ ] 我要求可验收了吗？

如果少了两项以上，先不要发给 GPT。

v0.2 核心训练扩写：让 GPT 围绕当前切片工作

本节扩写第 6 章。目标是把“会提问”变成“会控制输出边界”。

6.1 你不是在问 GPT，而是在给它划施工边界

很多新手把 GPT 当成一个“懂很多的顾问”。遇到一个想法，就问：

你觉得这个系统应该怎么做？

GPT 会回答，而且通常回答得很完整。但完整不等于适合当前阶段。

在 AI 协同开发里，你更应该把 GPT 当成一个非常能干、但容易主动扩展的协作者。它会补全你没说的内容，会替你做很多假设，会把一个小需求扩成一个完整系统。

所以，你给 GPT 的任务不能只写“我要什么”，还要写：

  1. 本轮只做什么。
  2. 本轮不要做什么。
  3. 输出格式是什么。
  4. 哪些内容必须放入待确认项。
  5. 哪些内容不能自行决定。

这不是为了限制 GPT 的能力，而是为了让它的能力服务于你当前的切片。

6.2 切片任务提示词的基本结构

一个稳定的切片任务提示词，建议包含 7 个部分。

1. 角色：你希望 GPT 以什么身份工作。
2. 背景：项目是什么，当前阶段是什么。
3. 当前切片：本轮只围绕哪条链路。
4. 明确禁止：哪些内容不要展开。
5. 输出目标：本轮要产出什么。
6. 输出格式：按什么结构输出。
7. 待确认项：不确定时不要脑补，列出来。

主案例示范：

你是一名 AI 协同开发教练，擅长帮助新手把模糊需求压缩成可施工切片。

项目背景：我在做一个 AI 员工任务系统。完整系统未来可能包含任务创建、审批、执行、记忆、工具权限和复盘。

当前切片：只围绕“用户输入任务 → 系统生成可编辑草案 → 用户确认 → 任务进入列表”工作。

明确禁止：不要展开真实 agent 执行、工具调用、多员工调度、长期记忆、复杂权限、数据库设计和部署方案。

输出目标：请帮我输出当前切片的页面预览、切片边界和待确认项。

输出格式：
1. 页面范围
2. 用户路径
3. 页面状态
4. 本切片做什么
5. 本切片不做什么
6. 待确认项

要求：所有你不确定的地方都放入待确认项，不要自行决定。

这个提示词看起来比一句话长，但它能显著降低 GPT 发散的概率。

6.3 “禁止展开”不是客气话，要写具体

很多人会在提示词里写：

不要太复杂。

这句话几乎没用。因为“复杂”是主观词。GPT 不知道你认为哪些内容复杂。

更好的写法是列出具体禁止项：

不要展开以下内容：
1. 真实 agent 执行。
2. 工具调用。
3. 多员工调度。
4. 长期记忆。
5. 高风险审批。
6. 权限系统。
7. 数据库设计。
8. 部署方案。

具体禁止项的好处是：

  • GPT 更容易遵守。
  • 你更容易检查输出是否越界。
  • 后续转成施工单时，coding agent 也更不容易顺手加功能。

6.4 三组错误问法 vs 正确问法

组 1：目标太大

错误问法：

请帮我设计一个 AI 员工系统。

可能输出：角色系统、任务系统、工具系统、记忆系统、权限系统、日志系统、部署架构。

正确问法：

请不要设计完整 AI 员工系统。请只围绕第一切片“任务创建 → 草案确认 → 进入列表”工作，输出页面预览和切片边界。

组 2：输出物不清

错误问法：

帮我分析一下这个功能。

问题：GPT 可能写市场分析、产品分析、技术分析、风险分析，但你当前需要的是可执行材料。

正确问法：

请把下面的功能改写成一页纸切片定义，字段包括：起点、终点、用户路径、做什么、不做什么、验收标准、待确认项。

组 3：让 GPT 默默脑补

错误问法：

缺的地方你自己补充。

这句话非常危险。GPT 会替你决定很多关键边界。

正确问法：

所有不确定或需要业务决策的地方，请放入“待确认项”，不要自行补充成确定方案。

6.5 主案例对话演示一：从产品合同到页面预览

用户输入给 GPT

你是一名 AI 协同开发教练。下面是一页纸产品合同：

功能名称：AI 员工任务创建与确认闭环
目标用户：管理者 / 任务发起人
本版闭环：输入任务 → 生成草案 → 人工确认 → 任务入列表
成功标准：3 分钟内创建任务；草案可编辑；空输入不能提交；确认后能看到任务状态
本版不做：真实执行、长期记忆、多员工调度、复杂权限

请不要写后端、数据库、agent 架构。
请只输出页面预览方案，包括：页面范围、页面区块、按钮、用户点击路径、空状态、加载态、错误态、待确认项。

GPT 理想输出应该长什么样

页面范围：
1. 任务创建页
2. 草案确认区
3. 任务列表区

用户路径：
1. 用户输入任务描述。
2. 点击“生成草案”。
3. 系统展示草案卡片。
4. 用户编辑草案。
5. 点击“确认创建”。
6. 任务出现在列表中，状态为“待执行”。

空状态：
- 输入框为空时，“生成草案”按钮禁用。
- 列表为空时展示：暂无任务，请先创建一个任务。

加载态：
- 点击生成草案后，按钮显示“生成中”。
- 草案区域显示加载提示。

错误态：
- 生成失败时提示：草案生成失败，请重试。
- 确认失败时提示：任务创建失败，请重试。

待确认项：
1. 草案字段是否包括风险等级？
2. 任务列表是否与创建页同页展示？
3. 第一版是否要求刷新后保留数据？

你要检查什么

你要检查 GPT 有没有越界。

如果输出里出现下面内容，就说明它跑远了：

数据库表结构
API 路由设计
多 agent 调度流程
权限模型
部署架构

这不是说这些永远不需要，而是它们不属于本轮页面预览。

6.6 主案例对话演示二：从页面预览到施工单草稿

用户输入给 GPT

基于下面的页面预览，请生成第一切片施工任务单草稿。

当前切片：任务创建 → 草案确认 → 入列表。
数据策略：使用 mock 草案生成和前端本地状态。
禁止展开：真实 agent、后端接口、数据库、审批、执行、权限、长期记忆。

请输出：目标、输入材料、交付物、实现范围、不做范围、验收标准、完成后需要汇报的内容。

GPT 理想输出

施工目标：
实现一个可交互的任务创建第一切片，用户可以输入任务、生成草案、编辑草案、确认创建，并在列表中看到任务。

输入材料：
1. 一页纸产品合同。
2. 页面预览方案。
3. 第一切片做/不做边界。

交付物：
1. 可运行页面。
2. mock 草案生成逻辑。
3. 任务列表状态展示。
4. 运行说明。
5. 变更文件清单。
6. 已知问题说明。

实现范围：
1. 任务描述输入框。
2. 生成草案按钮和加载态。
3. 草案卡片。
4. 草案字段编辑。
5. 确认创建。
6. 任务列表。

不做范围：
1. 不接真实 agent。
2. 不接后端接口。
3. 不做数据库持久化。
4. 不做审批。
5. 不做真实执行。
6. 不做权限和记忆。

验收标准：
1. 空输入不能提交。
2. 输入后可以生成草案。
3. 草案可以编辑。
4. 确认后任务进入列表。
5. 状态显示为“待执行”。
6. 页面不出现本切片之外的功能。

6.7 五种高频提示词模式

模式 1：压缩需求

请不要展开完整系统。请把下面的需求压缩成一个最小可验证闭环，并说明起点、终点、用户价值、做什么、不做什么。

需求：{你的需求}

模式 2：审查是否发散

请检查下面的输出是否偏离当前切片。
当前切片是：{切片定义}
禁止展开：{禁止项列表}

请标出所有越界内容，并说明应该删除、延后还是放入待确认项。

输出内容：{贴上 GPT 输出}

模式 3：把模糊话改成可验收表达

请把下面这些模糊描述改写成可验收标准。每条标准必须包含操作、期望结果和通过条件。

模糊描述：
{贴上描述}

模式 4：要求待确认项

请基于下面材料工作。所有不确定、需要业务判断、可能影响范围的内容，都不要自行决定，请放入“待确认项”。

材料：{贴上材料}

模式 5：生成施工前材料包

请基于当前第一切片，生成 coding agent 施工前材料包。
只输出：切片定义、页面范围、做/不做边界、验收标准、待确认项。
不要写代码，不要写数据库，不要写完整架构。

6.8 字段解释：切片任务提示词模板

角色

角色不是装饰，它会影响输出风格。你可以让 GPT 扮演：

  • AI 协同开发教练
  • 产品经理
  • 施工单审查员
  • 验收清单设计者
  • 返工单整理者

不要一次给太多角色。每轮只选一个。

背景

背景要够用，但不要塞太多历史材料。只给当前切片需要的信息。

当前切片

这是最重要的锚点。最好用一句话写清：

当前切片：用户输入任务 → 系统生成可编辑草案 → 用户确认 → 任务进入列表。

明确禁止

禁止项要具体。不要写“不要复杂”，要写“不要数据库、不要审批、不要真实执行”。

输出目标

告诉 GPT 这轮要产出什么，而不是让它自由发挥。

输出格式

格式越明确，你越容易检查。

待确认项

这能减少 GPT 脑补。

6.12 练习扩写与参考答案

练习 1：识别发散提示词

判断下面哪些提示词容易发散。

A. 请帮我设计完整 AI 员工系统。
B. 请只围绕任务创建第一切片输出页面状态。
C. 请把这个功能做成完整产品方案。
D. 请不要写架构，只输出验收清单。
E. 缺的你帮我补全。

参考答案：

容易发散：A、C、E。
不容易发散：B、D。

解释：A 和 C 范围过大；E 允许 GPT 脑补。B 和 D 明确限制了范围和输出物。

练习 2：改写发散提示词

原提示词：

我要做一个外贸获客系统，请帮我设计完整方案。

参考改写：

我想做外贸获客系统。请不要设计完整方案。请只识别第一条最小闭环：用户输入目标国家和产品 → 系统生成候选客户列表 → 用户标记是否值得跟进。请输出起点、终点、做/不做边界和验收标准。

练习 3：限制输出范围

参考答案：

当前只做第一切片“任务创建 → 草案确认 → 入列表”。不要展开审批、执行、员工配置、权限、记忆、数据库、部署。所有涉及这些内容的想法请放入“后续切片建议”，不要写进当前方案。

练习 4：要求待确认项

参考答案：

如果你发现材料中缺少业务规则，请不要自行决定。请统一放入“待确认项”，格式为：问题、为什么需要确认、如果不确认可能导致什么偏差。

练习 5：页面预览提示词

参考答案：

基于下面的一页纸产品合同，请只输出页面预览方案，不要写后端、数据库和接口。页面预览必须包括页面区块、按钮、用户点击路径、空状态、加载态、错误态和待确认项。

练习 6：验收清单提示词

参考答案：

请基于当前切片生成手工验收清单。每条验收项必须包含：前置条件、操作步骤、期望结果、通过标准。请覆盖正常流程、空输入、加载失败、重复点击和本版不应出现的越界功能。

练习 7：连续三轮对话设计

参考答案：

第一轮：请把模糊需求压缩成最小闭环。
第二轮：请基于最小闭环输出页面预览，不要写后端。
第三轮：请基于页面预览输出切片边界和验收标准，不要写代码。

这三轮的关键是：每一轮只要一个输出物。

练习 8：分析 GPT 输出是否越界

示例输出：

除了任务创建页，还需要设计员工权限表、任务执行队列、工具调用日志和部署架构。

参考答案：

越界内容：员工权限表、任务执行队列、工具调用日志、部署架构。
处理方式：从当前切片删除，放入后续阶段。
原因：当前切片只验证任务创建到入列表，不需要这些技术模块。

6.13 读者常见卡点

卡点 1：提示词写太短，结果失控

短提示词不是问题，问题是缺少边界。如果你只说“帮我设计一下”，GPT 会默认补全。

卡点 2：提示词写很长，但没有本轮目标

有些人把很多背景都贴进去，但不说这轮要什么。GPT 仍然会发散。

卡点 3：怕限制太多影响 GPT 发挥

早期开发不是头脑风暴，而是施工控制。你可以单独开一轮让 GPT 发散，但一旦进入切片施工，就必须收敛。

卡点 4：把 GPT 的输出当最终答案

GPT 输出是草稿，不是命令。你要用越界检查表审查它。

6.15 本章小结补强

GPT 很强，但它不会自动知道你当前处在哪个开发阶段。你必须告诉它：本轮只做什么，不做什么，输出什么，不确定时怎么处理。

记住一句话：

提示词不是许愿单，而是边界控制器。

如果你能稳定控制 GPT 的输出边界，后面给 coding agent 施工时，项目就不会轻易从小切片膨胀成大工程。
